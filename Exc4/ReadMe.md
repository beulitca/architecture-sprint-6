1. Взаимодействие  core-app и osago-agregator:
event-stream kafka, т к он уже есть у нас в системе. 
По нагрузкам можно было бы применить Apache ActiveMQAramis и воспользоваться механизмом push-ей, но оставим одну технологию для простоты поддержки.
2. osago-aggregator больше похож на чисто интеграционный сервис, поэтому своей базы не требует
3. osago-agregator должен поддерживать timeout ожидания информации от страховых компаний - 60 сек, такой же таймаут должен действовать при ожидании ответа на стороне core-app
4. api между core-app и osago-agregator: событие отправки заявки и событие получения расчета. Делать дополнительные события об успешной регистрации заявки на стороне страховой компании не вижу смысла, т к ожидание всего 60 сек, это загрузит сеть по всей цепочке. Обмен сообщениями по типу Data stream, когда на одну заявку по ОСАГО возвращается несколько ответов отдельно от каждой страховой компании по мере поступления.
5. Circuit Breaker хорош, когда есть альтернативные источники получения данных, либо если есть опасность превышения sla внешнего API. В данном случае явных кейсов его применения нет.
6. Retry, Timeout и Jitter могут использоваться для синхронного api обращения в страховую.
7. Rate limiting - можно ограничить число заявок по осаго от пользователя одним в минуту. Размещение не на клиенте.
8. Мы используем event streaming, где все сообщения имеют id, поэтому не должно возникнуть проблем с тем, что один экземпляр сервиса отправил заявку, а другой получил на нее ответ. По id события могут быть строго упорядочены и корректно обработаны.
